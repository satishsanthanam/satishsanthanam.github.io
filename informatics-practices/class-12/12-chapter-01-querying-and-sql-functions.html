Informatics Practices: Class 12 — Chapter 1: Querying and SQL Functions

1.1 Introduction & Database Schema

In database management systems, SQL (Structured Query Language) is utilized to populate, manipulate, and retrieve data from relational databases. This chapter builds upon basic SQL concepts to explore advanced querying mechanisms, single-row functions, aggregate functions, grouping operations, and multi-table relations using MySQL.

Technical Profile: CARSHOWROOM Database Environment

  • Architecture Layer / Tier: Relational Database Management System (RDBMS) / MySQL Backend
  • Operational Mechanics: Consists of four interconnected relations linked via primary and foreign key constraints to maintain referential integrity.
  • System Impact & Execution Outputs: Serves as the transactional and analytical data store for inventory tracking, customer sales, and employee management.
Database Schema & Relations

The CARSHOWROOM database consists of the following four relations:

  • INVENTORY: Stores name, price, model, year of manufacturing, and fuel type for each car in the showroom.
  • CUSTOMER: Stores customer ID, name, address, phone number, and email.
  • SALE: Stores invoice number, car ID, customer ID, sale date, mode of payment, sales person's employee ID, and selling price.
  • EMPLOYEE: Stores employee ID, name, date of birth, date of joining, designation, and salary.

1.2 Functions in SQL

SQL functions are built-in operations used to perform calculations, manipulate strings, or format dates. They are broadly categorized into Single Row Functions (Scalar) and Multiple Row Functions (Aggregate).

1.2.1 Single Row Functions (Scalar)

Single row functions operate on a single value from a single row and return a single value as output. They are categorized into Numeric, String, and Date & Time functions.

1.3 GROUP BY in SQL

The GROUP BY clause is used to group rows that have the same values in specified columns into summary rows. It is frequently used with aggregate functions to perform calculations on each group.

HAVING Clause

The HAVING clause is used to apply filter conditions on grouped records. Unlike the WHERE clause, which filters rows before grouping, HAVING filters groups after GROUP BY has been applied. 

  
    mysql> SELECT CustID, COUNT(*)
    FROM SALE
    GROUP BY CustID
    HAVING COUNT(*) > 1;
1.4 Operations on Relations

Relational algebra operations allow merging and manipulating tuples from two or more tables. These operations require the participating relations to be Union Compatible (same number of attributes, with corresponding attributes sharing the same domain).

Set Operations
  • UNION (U): Combines the selected rows of two tables, eliminating duplicate rows.
  • INTERSECT (∩): Returns only the common tuples present in both tables.
  • MINUS (-): Returns tuples present in the first table but absent in the second table.
  • Cartesian Product (X): Combines each row of the first table with every row of the second table. The degree of the resulting relation is the sum of the degrees of both tables ($Degree = D_1 + D_2$), and the cardinality is the product of their cardinalities ($Cardinality = C_1 \times C_2$).
1.5 Using Two Relations in a Query

To retrieve data from multiple tables, SQL provides mechanisms to perform Cartesian products and Joins.

Cartesian Product & Joins

When multiple tables are specified in the FROM clause separated by commas without a join condition, a Cartesian product is performed. 

  
  mysql> SELECT * FROM DANCE, MUSIC;

JOIN Operations:

  • Equi-Join: Joins tables based on an equality condition between common columns using the WHERE clause.
  • Explicit JOIN Clause: Uses the JOIN keyword along with the ON clause to specify join conditions.
  • NATURAL JOIN: An automated join that matches columns with identical names in both tables and automatically eliminates duplicate columns from the output. 
  
  mysql> SELECT * FROM UNIFORM NATURAL JOIN COST;
